Chorus lets AI layers share one word-sequence table, cutting memory by 87%

Some language models add capacity cheaply with n-gram embedding tables. These are big lookup tables of learned numbers for short runs of words. Newer designs give each layer of the model its own table, which uses a lot of memory. A single shared table performed poorly. Researchers propose Chorus, which uses one set of tables for the whole network. Each layer reads it in its own way, using its own projection and scaling based on its current state. Chorus matched existing methods with 87% smaller tables. With 1.2B table parameters, it predicted text better than FactorEngram and DeepSeek's Engram did with 9.6B. It beat Engram, TN-gram and FactorEngram in every comparison. Paired with the Ember optimizer, it saved 99.2% of optimizer memory versus AdamW without hurting training. This could make larger tables easier to build.
